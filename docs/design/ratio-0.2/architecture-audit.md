# Ratio interface architecture audit

Audited baseline commit `23fa118`. The read-only application review used the local Luma workspace at port 4178, authenticated Chromium, the repository’s Maud and browser sources, and rendered desktop and phone captures. Local browser probes changed filters, focus, disclosures and a tab-scoped note draft. They submitted no business records. Server-side integration, native-wrapper contracts and provider branches were inspected in source. Live Stripe, GitHub, physical touch devices and screen-reader output were outside this baseline check.

## What the rendered product reveals

| Priority | Evidence and impact | Smallest durable design change |
| --- | --- | --- |
| P1 — Scope and navigation | A 1,440 px window reserves 240 px for navigation and offers 15 simultaneous links in the seeded rail, before the account controls. “Workspace / My issues” above “Issues” and the selected rail link spend three locations on the same identity. Project-specific pages still have a generic location. The shell search link and its printed shortcut produce different result scopes on a project. | Give the shell one primary location and one consistent scoped search destination. Preserve every route via progressive disclosure of lower-frequency management destinations. Project membership belongs in the location and genuine record metadata. |
| P1 — Creation interrupts the work | On the 19-result issue list the existing C shortcut scrolls 869 px in a 900 px viewport to the form beneath every result. It opens a full page of editing controls and leaves the operator looking away from the relevant issue group. The aggregate sits at one height, a second header supplies layouts, a third labels columns and a fourth labels the group. The first record starts at y=258 desktop and y=275 on a 390 px phone. | Put the single existing creation form close to its invoking action. Keep its hash, focus and ordinary submit. De-emphasize advanced issue properties until requested. Choose a tighter content/header rhythm and make the record title the reading anchor. |
| P1 — Adjacent routes feel unrelated | Issues and projects have authored rows and responsive layouts. `notes::views::list` instead emits an `article.row` with a title/path and free-floating project/revision. The capture reads as a clump of links; it barely occupies the corner of a 1,117 px usable page. Transfer gives each file picker, project selector and folder field that same 1,117 px width. The settings text field is already constrained to 440 px. | Introduce an actual record-list layout, a measured form layout and a consistent section or inspector header. Pick by content type. Use a readable form measure and a full-width track for rows and charts. |
| P1 — Controls and feedback lack roles | Generic `button`, `.btn` and `.button` styles assign competing defaults. Unclassified actions read as primary. `.panel`, `.content-section` and `.plan-card` share a border-top and unconstrained children. `.notice` and `.empty` have nearly identical presentation whether an error, provider limitation, empty query or ordinary informational message caused them. | Define primary, secondary, quiet and destructive actions. Give action groups a shared baseline. Define a compact inline message, contextual error and actionable empty state. Assign them explicitly to the existing control and response. |
| P1 — Small controls are hard to target | The mobile issue search field used 13 px type and a 26 px-high inner field. Its submit target was 24 px high. Icon buttons were 29 px and basic settings fields 34 px high at 390 px. Search is visually reordered below Filter/Display at 650 px while its keyboard order stays before them. | Separate desktop visual density from coarse-pointer targets. Use a larger visible or padded mobile hit area, a readable mobile input size and source order consistent with the rendered toolbar. Keep the browser zoomable. |
| P2 — Strokes and surfaces carry too much weight in some places and too little in others | Graphite `--control-line` against the text field surface measures 2.37:1 and against the canvas 2.49:1. Faint text already measures 5.98:1 against canvas and ordinary text 15.39:1. Section rules, active states and field boundaries serve different purposes. Some critical record metadata is shown through the same filled/outlined shapes as presentation-only counts. | Separate decorative separators, field boundaries, keyboard ring, selection, status and risk. Test token pairs against the actual local surface in both display preferences. Keep redundant status shapes and text. |
| P2 — Menus look alike while behaving differently | Filter/Display and the mobile navigation support Escape, outside click and focus return via `workspace.js`. Board status and detail status are inline disclosures; the board one stayed open on Escape. Grouping, data disclosure, destructive confirmation and temporary popovers all derive from bare `details`, with global `details[open] > summary` spacing. | Reserve popover behavior for floating controls, with an explicit shared hook and focus contract. Keep ordinary reading or editing disclosures in flow. Give the actions visual treatments that predict their behavior. |
| P2 — Error recovery is a separate product surface | `AppError::into_response` supplies a status-correct public shell and fixed Home link. Failed project validation and import commits can leave the field or preview behind. Notes already implement conflict recovery with submitted text and revision. | Preserve all server status codes and validation. Improve field help association and the generic message presentation. For high-frequency edits, reuse the note-style local recovery design where a handler can safely re-render values. Avoid claiming universal recovery until each handler does it. |

## Engineering boundaries

- `src/ui.rs` owns the global shell, two renderings of `navigation` for different screen sizes, `icon`, document metadata, shared CSRF field and public document. `src/auth.rs::public_page` independently renders the login/recovery brand, head and form shell with its own referrer settings. `src/lib.rs` embeds and allowlists styles and fonts at compile time. Changes require a rebuilt service; editing stylesheet files alone cannot alter a running binary.
- `assets/app.css` imports type, issue, detail and project styles before global rules. Equal-specificity global defaults can supersede feature rules. Features compensate with compound selectors or page attribute selectors. The foundation has color/type aliases and two layout widths, but lacks reusable spacing steps, action sizes, radius, heading, field-boundary and focus tokens. Split a small ordered foundation → primitives → local layout; verify the embedded URLs and imports in a real response. The existing Instrument Sans and IBM Plex Mono assets are local and licensed.
- `src/issues/pages.rs::{issue_row,issue_results,filter_bar,new_issue,detail,edit_issue,status_form}` contain real server filtering, pagination, group ranges, mutations and history. `ledger_icon` uses a different view box from `ui::icon`; status/priority marks have meaningful shape semantics. Home issue rows in `src/issues.rs::home` and project queue rows in `src/projects.rs::overview` have similar data but different DOM. Share ID, title, status, priority and section styles without forcing the board, ledger, command forms and checkpoint narrative into one markup tree. Preserve group counts' page-local meaning, all matched totals, critical and archived state, exact POST names, command UUIDs, CSRF and revisions.
- `assets/workspace.js::{currentProject,goToIssues,focusDestination,openHelp}` preserve URL filters on the issue route and determine project context from the project path, URL filter or issue breadcrumb. The visible hyperlink is rendered separately in `ui::page`. With a project open, pointer search returned `/issues#search`; keyboard search returned `/issues?project=<id>#search`. Generate or enhance one canonical href and have input methods use that destination. Preserve single-key opt-out and migration keys, composition/editable guards, back/forward, search fragment and creation fallback. Inbox is `/issues?status=backlog`: C correctly retained Backlog in the running application.
- `src/projects.rs::{index,overview,project_form,project_list,issue_progress}` give the directory and overview distinct CSS grids, numeric completion values and next-milestone dates. The free demo account has a genuine cap, so the unavailable create form must remain conditional. Test archived projects and long keys. Avoid fake “New project” buttons.
- `src/notes/views.rs::{list,edit,preview,recover,detail,confirm_delete}` and `src/notes/editor.js` operate real Markdown with fragment links, approved link suggestions, tab-local drafts, revision conflicts and explicit confirmations. Keep `data-note-editor`, draft actions/status markers, field names, preview submitter `formaction/formnovalidate` and recovery banners. The textarea is editable reading content; give it width and line-height independent of list/metric rows.
- `src/auth.rs`, `src/github/settings.rs`, `src/transfer/views.rs::{index,review}`, `src/billing/page.rs::{show,plan_card,resource_choices}` and `src/workflows.rs` are semantic-HTML forms and response-driven states. Transfer needs the provider-specific limits, scoped review table, real file `multipart/form-data`, conflict radios and unchanged preview/commit gating. Billing needs free/paid/unavailable/proration states. Integrations includes true disabled-provider, active and paused coverage states. Match section hierarchy and field measures; open advanced instructions only when needed and keep meaningful error/terms accessible.
- `src/roadmap/timeline.rs` and `src/roadmap/timeline.css` already provide an agenda alternative, real dates, real drilldowns, responsive layout and representations beyond color. SVG marks in `src/releases/insights.rs::plot` and source tables, history charts, forecast interval, and note graph form separate local renderers. Retain factual plotted values, keyboard links, legends, data tables and no-data cases. With dense history, a tab stop per insight point can delay reaching the data controls; offer a direct route to tabular data. `src/notes/graph.rs::compact_diagram` omits the section in an edge's accessible name where `lane_diagram` includes it. Two fragment destinations can sound identical.
- `src/sync.rs::head` adds workspace revision context for desktop. `assets/device-sync.js` locates `.page-content[data-view]`, treats interaction/dirty fields, selections, open forms, dialogs and the open mobile menu as reasons to defer automatic navigation, and announces offline and new-data states. Preserve these semantics if class or disclosure hooks change. `desktop/src/runtime*.rs` supplies pinned-origin navigation, external handoff, native history shortcuts and recognized transfer downloads. The separate connection sheet is in `desktop/assets/connect.html`. Its local launcher and remote workspace have distinct privilege boundaries.

## Reference decisions

Linear’s documentation shows filters and display preferences have separate jobs: one chooses records, the other chooses their organization. Its interface redesign treated the navigation rail and top bar as one structure and tested full workflows across browser and desktop. Ratio can retain its small command vocabulary and a precise, contextual creation workflow. Its full-row links are appropriate; bulk selection would require a real new product capability. [Linear display options](https://linear.app/docs/display-options) · [Linear issue creation and selection](https://linear.app/docs/creating-issues) · [Linear interface redesign](https://linear.app/now/how-we-redesigned-the-linear-ui)

Vercel’s guidance calls for generous mobile hit targets, unobscured keyboard focus, reversible navigation, shareable view state, accessible changes and contextual form errors. The existing URL-driven filters, native label/controls, dialog focus return and project-specific commands are assets. Use the guidance to correct mismatched control size, ordering, scope and recovery. [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)
