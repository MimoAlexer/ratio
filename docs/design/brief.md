# Design a Premium, Linear-Inspired Developer Application

You are a world-class senior product designer and frontend engineer with exceptionally strong visual taste. Your task is to design a sophisticated project management application built specifically for solo software developers.

The application should feel as refined, cohesive, and carefully engineered as Linear, Raycast, or other exceptionally well-designed productivity software.

**Your highest priority is to eliminate the recognizable "AI-generated UI" aesthetic.**

I would rather have a simple, exceptionally polished interface than an elaborate interface that looks AI-generated.

## 1. Design philosophy

Design this as a real software product that an experienced design team has refined over hundreds of iterations.

Every design decision must feel intentional.

- Take inspiration from Linear's information density, typography, interaction patterns, navigation, and precision.
- Develop an original visual identity instead of directly copying Linear.
- Prefer understated sophistication over visual spectacle.
- Create a UI that looks practical, expensive, mature, and exceptionally well-crafted.
- Let typography, alignment, spacing, hierarchy, and subtle color choices carry the design.
- Embrace functional complexity where appropriate. Real developer tools do not need to look like oversimplified landing pages.
- Optimize for someone who spends several hours per day using the application.

**The application must look designed, not generated.**

## 2. Absolutely avoid AI slop

These are strict design constraints, not suggestions.

DO NOT use:

- Generic SaaS dashboard templates or a typical shadcn/ui starter aesthetic.
- An excessive number of rounded cards and floating containers.
- Giant border radii on every element.
- Purple-to-blue gradients, glowing orbs, excessive glassmorphism, or artificial neon effects.
- Large, empty hero sections inside the actual application.
- Generic "Welcome back" dashboard sections.
- Decorative charts, statistics, illustrations, or icons without a genuine purpose.
- Excessive whitespace that sacrifices information density.
- Oversized typography on ordinary application screens.
- Pill-shaped buttons for everything.
- Random colored icon backgrounds.
- Excessive shadows, thick borders, or unnecessary visual layers.
- Perfectly symmetrical grids of cards when a more functional layout makes sense.
- Emoji-based navigation.
- Placeholder content that makes the interface feel like a mockup.
- Identical visual treatment for components that serve different functions.

Do not interpret minimalism as removing detail. A premium interface is defined by the quality of its details.

If a design looks like something generated in 30 seconds by a generic AI website builder, reject it and redesign it.

## 3. Color and visual identity

I do NOT want a plain black-and-white theme.

Create a restrained, distinctive color system that feels premium without being flashy.

Suggested direction:

- Dark, slightly tinted charcoal backgrounds rather than pure black.
- Carefully chosen neutral surface colors with subtle temperature differences.
- Muted indigo, steel blue, or desaturated violet as a primary accent.
- Intentional secondary colors for issue priorities, statuses, and meaningful feedback.
- Soft, restrained separators instead of heavy borders.
- Exceptional contrast management and text legibility.
- Subtle hover and selection states.

Use color sparingly, but meaningfully.

The result should feel cohesive and recognizable even without a logo.

Avoid defaulting to the same purple-accented dark dashboard that AI models repeatedly generate.

## 4. Layout and structure

Build a desktop-first interface that prioritizes speed, clarity, and information density.

The core application should include:

**Sidebar**
- Compact, structured navigation.
- Workspace identity and project switching.
- Inbox, My Issues, Projects, and other relevant sections.
- Clear active, hover, and focused states.
- Thoughtful icon sizing and alignment.
- No oversized navigation elements.

**Main workspace**
- A precise, compact header.
- Contextual navigation and useful actions.
- Clean, information-dense issue lists.
- Carefully designed status, priority, and project indicators.
- Inline metadata presented with excellent visual hierarchy.
- Filtering, sorting, grouping, and keyboard-oriented workflows.

**Issue detail view**
- Exceptional typography and content hierarchy.
- An integrated metadata panel.
- Thoughtful editing interactions.
- Subtle separation between descriptions, activity, and properties.
- A professional, focused writing and editing experience.

**Projects**
- Clear progress indicators.
- Useful project summaries.
- List and board views where appropriate.
- Functional information architecture rather than decorative dashboard widgets.

## 5. Typography, spacing, and microdetails

Pay obsessive attention to details that distinguish exceptional software from average software.

- Establish a consistent spacing scale, but permit optical adjustments.
- Use a high-quality modern UI typeface, such as Inter or Geist.
- Create a deliberate typography hierarchy with nuanced font weights.
- Keep rows compact without feeling cramped.
- Align icons, text baselines, controls, and separators precisely.
- Use restrained corner radii appropriate to each component.
- Design subtle hover, focus, selected, loading, empty, and disabled states.
- Make keyboard shortcuts and command menus feel native to the experience.
- Favor quiet, responsive transitions over decorative animations.
- Use a consistent icon family with restrained stroke weights.

The smallest details matter.

A one-pixel alignment issue, inconsistent padding, or poorly chosen background color can undermine the entire visual experience.

## 6. Product realism

This is a real project management application for solo developers, not a marketing concept.

Design around realistic developer workflows:

- Managing multiple personal software projects.
- Creating and organizing issues.
- Managing backlogs and development cycles.
- Tracking bugs and feature requests.
- Switching quickly between projects.
- Finding issues through search and keyboard shortcuts.
- Viewing progress without unnecessary management overhead.

Populate the interface with believable project names, issue titles, identifiers, priorities, labels, timestamps, and descriptions.

The interface should look like someone is actively using it to build software.

Avoid fake analytics, unnecessary enterprise features, and decorative data.

## 7. Creative independence

Do not blindly follow generic UI conventions.

You have permission to challenge standard layouts, adjust component structures, create subtle custom design patterns, and make independent visual decisions whenever they improve the result.

Do not use a component simply because a popular component library provides it.

Choose the design solution that best serves the product.

Reference Linear for its level of craftsmanship, not as a template to reproduce pixel for pixel.

## 8. Quality control

Before presenting the result, critically evaluate the interface.

Ask yourself:

1. Does this look unmistakably AI-generated?
2. Could this be confused with a generic dashboard template?
3. Does every visible element have a purpose?
4. Is the typography genuinely refined?
5. Does the color palette feel distinctive but restrained?
6. Is the information density appropriate for professional developer software?
7. Does the interface feel like a coherent product rather than assembled components?
8. Would this design look credible alongside Linear or Raycast?

If the answer reveals a weakness, revise the design rather than accepting a mediocre result.

Do not sacrifice quality for speed.

## 9. Deliverable

Start with the main issue management workspace, since it establishes the application's core design language.

Create a polished, production-quality interface with a coherent design system, including colors, typography, spacing, component treatments, navigation, and interaction states.

Prioritize the actual visual result over lengthy explanations of design theory.

Make decisive design choices. Do not provide several generic alternatives or ask unnecessary aesthetic questions.

**The ultimate goal: An interface that feels like it was designed by a talented human product designer who spent weeks refining every detail — not a generic application assembled by AI.**
